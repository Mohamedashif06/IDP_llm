Abstract—Institutions handle many kinds of paper and digital documents, such as mark sheets, certificates, invoices, identity cards (ID cards), attendance registers, and administrative forms, that mix printed labels with handwritten or irregularly placed values. Staff need structured spreadsheets, but Optical Character Recognition (OCR) recovers characters without field structure, so each new document type needs its own custom mapping script. Sending such documents to a hosted model also raises severe privacy and data-protection concerns for sensitive institutional records. This paper presents an Intelligent Document Processing (IDP) system that first classifies an uploaded photograph, scan, or Portable Document Format (PDF) file, then extracts its fields into an Excel workbook using an open-weight Qwen Vision-Language Model (VLM) served through Ollama on institution-controlled hardware. A JavaScript Object Notation (JSON) schema selected for the document type constrains the output, so a new document type needs only a schema edit. Blank or low-confidence fields are routed to a human reviewer before export. The system is deployed as a shared web service for multiple users on an internal network. On 45 documents of 5 types, the classifier was correct for 95.6% of documents, field-level exact-match accuracy was 99.4%, and 100.0% of incorrect or blank fields were flagged for review. The local model was compared with a hosted model and Tesseract on the same pages, and the average time was 3.4 s per page on local GPU hardware. Results come from a small test set and should be read as a proof of concept.
Index Terms— Intelligent document processing (IDP), document classification, optical character recognition (OCR), vision-language model (VLM), Qwen, Ollama, local inference, Excel export, schema-constrained JSON, human-in-the-loop review.
